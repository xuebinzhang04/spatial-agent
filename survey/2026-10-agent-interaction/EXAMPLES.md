# Twelve Interaction-Task Mechanisms

These are **project construction examples**, not reproduced benchmark tasks or evidence of running the cited systems. The [literature matrix](LITERATURE.md) separates reading depth from project inference.

| Mechanism and source | Concrete interaction | Generate and verify | SpatialAgent insight |
| --- | --- | --- | --- |
| 1. Terminal repair — [TMax](https://arxiv.org/abs/2606.23321), [SWE-Gym](https://arxiv.org/abs/2412.21139) | Inspect inconsistent CSVs → merge → run tests → fix errors → deliver totals. | Sample schemas, errors, and dependencies; check output values, edge cases, and unchanged inputs. | World state and execution feedback matter more than claimed completion. |
| 2. Cross-app binding — [AppWorld](https://arxiv.org/abs/2407.18901), [AutoForge](https://arxiv.org/abs/2512.22857) | Find attendees → resolve contacts → create list → attach its ID to event. | Build typed dependency DAG; check final and protected state, accepting alternative valid calls. | Keys, doors, objects, and orders also require binding across actions. |
| 3. Clarification and dual control — [ToolSandbox](https://arxiv.org/abs/2408.04682), [τ²-Bench](https://arxiv.org/abs/2506.07982) | Search two people named Alex → ask user → enable setting → send to agreed recipient. | Split hidden/user/tool facts; verify preconditions, recipient, and repeated-run reliability. | Information requests can become spatial actions; v1 has no simulated user. |
| 4. Dynamic events — [ARE](https://arxiv.org/abs/2509.17158), [Gaia2](https://arxiv.org/abs/2602.11964) | Meeting time changes → recheck conflicts → update booking. | Seed event time and visibility; score latest constraints and stale operations. | A road closure should force a new observation and plan. |
| 5. Web/desktop artifacts — [WebArena](https://arxiv.org/abs/2307.13854), [OSWorld](https://arxiv.org/abs/2404.07972) | Filter orders → export CSV → compute totals → attach file. | Reset apps/files; check artifact content and attachment, not an answer string. | Keep action granularity and budgets fixed in comparisons. |
| 6. Hidden-rule experiments — [ScienceWorld](https://arxiv.org/abs/2203.07540), [TextWorld](https://arxiv.org/abs/1806.11532) | Acquire samples/instrument → configure test → observe conductivity → choose material. | Sample hidden properties and repeatable measurements; check legal experiment and outcome. | Signal Repair instantiates this mechanism: local inspection reveals hidden fault type before matching-tool repair. |
| 7. Instruction composition — [BabyAI](https://arxiv.org/abs/1810.08272), [gSCAN](https://arxiv.org/abs/2003.05161) | Find key → open door → place red object left of blue. | Compile goal grammar into state rules; hold out combinations; verify order and geometry. | Current families isolate mechanisms; this cross-family chain is future work. |
| 8. Procedural rules — [Procgen](https://arxiv.org/abs/1912.01588), [XLand](https://arxiv.org/abs/2107.12808) | Learn key-door mapping; test a changed rule in a new map. | Vary layouts, entities, rules, and goals separately; audit each holdout. | New seeds alone do not establish new abilities. |
| 9. Shared resources — [Crafter](https://arxiv.org/abs/2109.06780), [Craftax](https://arxiv.org/abs/2402.16801) | Gather → craft tool → mine while retaining survival resources. | Enforce recipes and conservation; report whole-chain success and achievement coverage separately. | Battery, time, and capacity must persist across delivery subtasks. |
| 10. Automatic curriculum — [PAIRED](https://arxiv.org/abs/2012.02096), [ACCEL](https://arxiv.org/abs/2203.01302), [EnvGen](https://arxiv.org/abs/2403.12014) | Detect failure at depth two → sample verified depth-two tasks → re-evaluate on fixed holdout. | Track admission, policy failure, and learning progress; reverify mutations. | Adjust ability parameters only after task validity is established. |
| 11. Active spatial belief — [Theory of Space](https://arxiv.org/abs/2602.07055), [VAGEN](https://arxiv.org/abs/2510.16907) | Explore room → target moves → seek new evidence → deliver to current location. | Pair observation changes under fixed state semantics; score task plus belief diagnostics. | Symbolic SVG is not real visual training; task success remains primary. |
| 12. DeliveryBench extension — [DeliveryBench](https://arxiv.org/abs/2512.19234) | Accept two orders → wait for preparation → route pickups → recharge → deliver on time. | Import roads/POIs; verify graph moves, order state, capacity, battery, deadlines, and certificates. | Graph rules and chargers are synthetic; compare with native UE state before transfer claims. |

The common pipeline is **mechanism/dependency sampling → world and goal program → feasible certificate → observation-limited rollout → empirical difficulty → curriculum update**. Audit generator errors separately from policy failures.
