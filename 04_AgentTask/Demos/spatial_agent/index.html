SpatialAgent

Interactive tasks for training spatial memory

Research project · Work in progress
Tasks & cases Step through a case

Overview

Spatial memory matters both when a model watches a scene passively and when it explores to finish a task. We build interactive tasks in which memory is necessary, on the hypothesis that interaction trains it better than passive viewing.

Each task separates the agent's local state (what it sees at one step) from a global memory it must build, update and freeze across steps. Every case is generated so that an information gap can only be closed by acting, and is scored by a verifiable environment check rather than by a judge. The goal is to use these tasks as reinforcement-learning environments and test transfer to spatial benchmarks such as VSI-Bench and Theory of Space.

Buildobserve and record object locations, routes or shape views
Updatethe world or the agent's pose changes; stale memory must be revised
Freezea committed memory is the reference the answer is checked against

    Generation audit: controls, memory variables and checks for every generated case
  
    
    
    Task Generation & Memory Variables
    
    
    Spatial memory is needed both when watching passively and when exploring to complete a task; interaction is meant to strengthen it. Each task therefore separates the local state a policy observes at one step from the global memory it must build, update and keep frozen across steps (as in Theory of Space, where belief is built, revised and frozen). Each task's global memory needs well-defined environment variables and a way to score them. Here every generated case is audited from its controls (seed, level, configuration) to the global-memory variables it produces. Checks verify that each control has its declared effect, that the same recipe regenerates the same case, and that the variables admit the intended memory use. A warning marks an admissible case that is weak for memory training.
    
    
    
    
    No generation audit is bundled with this build.
    
    
    Global-memory values are evaluator-side variables shown for research presentation; policies never receive them. Recorded episodes may predate current generation protocols; fresh generation reflects the current code.

    Research Notes
    
    
    Task Construction and Verification
    
    
    Task generation combines scene parameters and interaction requirements, validates the initial state and feasible execution, and binds an explicit correctness predicate. For example, container retrieval requires opening the source before pickup and restoring closure; relational placement must also preserve protected objects. Dynamic replanning requires a physically verified obstruction and an executable detour.
    
    
    Structural levels increase requirements such as ordered visits, retrieval orders, or conjunctive spatial relations. Their empirical difficulty still needs calibration through repeated policy rollouts. The intended learning loop is generation, interaction, verification, difficulty calibration, and training, followed by evaluation on held-out instances.
    

    
    Current Evidence and Next Experiments
    
    
    The catalog contains  task families with  recordings, including  model recordings. Oracle trajectories use privileged state and establish feasibility. The historical spatial smoke attempts have no strict successes; a fixed courier case has a separately verified Qwen completion. These development examples do not constitute a controlled policy comparison. Difficulty calibration, RL training, and transfer evaluation remain future work.
    
    
    Diagnostic example. In one Qwen3.8-27B missing-object attempt, the model identifies the change but reports the previous location incorrectly. Reward is 0.925 while strict success is false. This motivates evaluating complete spatial objectives alongside partial progress.
    
    
    Next experiments. Compare matched task instances and budgets with memory retained or cleared, containers initially open or closed, and a checkpoint event present or absent. Then calibrate difficulty and test RL on held-out scenes and task compositions.
